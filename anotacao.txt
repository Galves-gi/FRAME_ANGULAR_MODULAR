{

  loadChildren: () =>
    import('./features/feed/feed.module').then(m => m.FeedModule)
}


- loadChildren

Essa propriedade indica Lazy Loading.

👉 Angular NÃO carrega o módulo imediatamente
👉 Ele só carrega quando a rota é acessada

📌 Benefícios:
✔ Performance
✔ Menor bundle inicial
✔ Escalabilidade


- import('./features/feed/feed.module')

Isso é um import dinâmico (JavaScript moderno).
Diferente de import { FeedModule } from ...
Só busca o arquivo quando necessário

- .then(m => m.FeedModule)

    - m é o módulo importado
    - Retorna qual módulo Angular será carregado

👉 Angular precisa disso para:
    - Registrar componentes
    - Registrar rotas internas do módulo

    CommonModule,

2-
app componentes

importa o module pai que quero exibir os componentes filhos

app.component.ts
import { Component } from '@angular/core';
import { RouterOutlet } from '@angular/router';
import { paiModule } from './shared/shared.module';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [
    RouterOutlet,
    paiModule   // 👈 AQUI
  ],
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css']
})
export class AppComponent {}

3-
Desativar o Standalone padrão do angular
vai em: tsconfig.app.json

adiciona:
  "angularCompilerOptions": {
    "strictStandalone": false
  }


✔ Angular 17 não cria AppModule

✔ Shared / Core / Features usam NgModule
✔ Root pode ser standalone
✔ AppComponent importa SharedModule
✔ Nada fica “solto”

core:  Interceptor


- HTTP Interceptor

Supervisona as requisições http, tudo que for sair, as respostas que recebe e tudo que chega no componentes

Component / Service
        ↓
   Interceptor(s)
        ↓
      API
        ↓
   Interceptor(s)
        ↓
Component / Service


- Interceptor de LOADING

Como funciona
1️⃣ Requisição inicia → mostra loading
2️⃣ Requisição termina (success ou error) → esconde loading
